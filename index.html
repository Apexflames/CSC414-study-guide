CampusChef, a cautionary tale. A developer builds a great idea — a student-to-student meal delivery app. But the homepage is cluttered with five equally-loud buttons, there's no clear "Order Now," a "Find Food" tap opens a blank screen, and Back freezes the app. Five minutes later, the user deletes it. 1. Introduction to HCI & Usability

What is HCI?

Source
Human-Computer Interaction (HCI) is the study, planning, and design of how people interact with computers. It is basically the interaction between people end-users and computers.
Plain EnglishIt's not just about building apps — it's about making sure the technology actually works for the humans using it.

HCI is interdisciplinary, drawing from: Computer Science (software/hardware, programming interfaces), Psychology (how humans think, perceive, learn, remember), Design (attractive, usable layouts), Cognitive Science (attention, memory), Ergonomics (physical comfort/safety), Linguistics (natural language interfaces), and Artificial Intelligence (intelligent software).

Goals: Usability vs User Experience

Source
Usability refers to how easy and effective it is for users to interact with a system. User Experience (UX) goes further — it covers how users feel about using the system, including satisfaction, comfort, and emotional response.
QualityMeaningExample
Easy to learnFirst-time users figure it out quicklyA food-ordering app that guides new users clearly
Easy to rememberReturning users recall it without relearningThe Search button stays where you expect it, months later
Effective to useUsers accomplish goals accuratelyBooking a flight without confusion
Efficient to useTasks completed quickly, minimal effortShortcut keys, autofill
Safe to usePrevents serious errors, allows recovery"Are you sure you want to delete?" prompt
Enjoyable to usePleasant, not stressfulFriendly messages, good feedback

Quick Revision — Introduction

  • HCI = study/planning/design of people ↔ computer interaction; interdisciplinary (CS, Psychology, Design, Cognitive Science, Ergonomics, Linguistics, AI).
  • Usability = easy & effective. UX = usability + feelings (satisfaction, comfort, emotion).
  • Six usability qualities: learnable, memorable, effective, efficient, safe, enjoyable.

2. The User Interface

Source
The user interface is the part of a computer system and its software that users interact with. It has essentially two components: input and output.

Interaction involves the human senses: Sight (text, icons, colours, layout), Touch (mouse, keyboard, touchscreen, gestures), Hearing (audio feedback, alerts, voice), and increasingly Speaking (voice commands).

Importance of the User Interface

  • It's the user's window into the system — how they view and access its features.
  • It's the medium for performing critical tasks that affect satisfaction and profitability.
  • It shapes how users perceive the system's reliability — a poor interface makes a powerful system look untrustworthy.
  • It affects task efficiency and accuracy — confusing layouts cause mistakes and delay.
  • It determines user retention — bad interfaces drive users to alternatives.
  • It impacts emotions and stress — a clean interface reduces cognitive load.

3. History & Evolution of UI Design

Command-Line Interfaces (CLIs)

Text-based; users memorised and typed exact commands, needed programming knowledge, and had no visual indication of what was being deleted or whether it was recoverable. Example MS-DOS, Unix shell.

GUIs and the WIMP Model

Source
GUIs emerged in the 1980s, notably with the Xerox Star, Apple Lisa, and later Macintosh. They introduced windows, icons, menus and pointers (WIMP), reducing memory load, giving immediate visual feedback, and being easier to learn especially for non-technical users.
WIMP ElementDescriptionExample
WindowsIndependent viewing areas for apps/contentTwo Word docs open side by side
IconsSmall visual symbols for files/tools/actionsTrash-can icon = delete
MenusLists of available commandsFile → Save As
PointerMovable on-screen cursorClicking with a mouse or finger

Visual Metaphors

Source
A visual metaphor is a design technique where real-world objects or concepts are represented visually in the digital interface, using familiar images to represent digital actions — making the interface more intuitive and easier to learn.
  • Object-based — real-world objects: folder, trash bin, desktop.
  • Action-based — represents behaviours: drag-and-drop mimics physically moving files.
  • Environmental — simulates a physical space: the desktop metaphor arranges icons like items on a real desk.

Web-Based Interfaces

Emerged mid-1990s with the rise of the internet — HTML/CSS/JavaScript, accessed via browser, shifting design emphasis to hyperlinks, forms, scrollable content and responsive layouts. Examples: Gmail, Amazon, Google Search.

Mobile & Touch Interfaces (2007–present)

Introduced by the iPhone/Android; touch gestures (tap, swipe, pinch) replaced mouse functions, with emphasis on minimalism, flat design and responsive design.

Modern Interfaces (2015 onward)

Voice interfaces (Siri, Alexa), Augmented/Virtual Reality, conversational UIs (chatbots), and multimodal interfaces (voice + touch + vision).

GUI vs Web UI

FeatureGUI (Desktop)Web UI (Browser)
PlatformLocal apps (e.g. Photoshop)Browser-accessed (e.g. Google Docs)
PerformanceFast, uses system resourcesDepends on internet/server speed
Interaction styleTool-focused, deep menusNavigation-focused, hyperlink-driven
CustomizationPersonalisableLimited by HTML/CSS/browser
ExamplesMS Excel, PhotoshopAmazon, Gmail, Coursera

Quick Revision — History & Evolution

  • CLI (text, memorised commands) → GUI/WIMP (windows, icons, menus, pointer) → Web UI (browser, HTML/CSS/JS) → Mobile/Touch (gestures) → Modern (voice, AR/VR, conversational, multimodal).
  • Visual metaphors: Object-based, Action-based, Environmental.
  • GUI = feature-rich, local; Web UI = accessible, hyperlink-driven.

5. Principles of User Interface Design

Source
Design principles are guidelines that help interface designers create systems that are usable (easy to learn and use) and consistent (uniform and predictable).

Why Design Principles Are Needed

  • Guide consistency across screens.
  • Reduce user errors (disabling unavailable options, confirming destructive actions).
  • Improve learnability and efficiency.
  • Provide a framework for evaluation during prototyping and testing.
  • Support a user-centred design approach — needs, accessibility, context of use.

General Principles

  • Shneiderman's 8 rules — consistency, shortcuts, feedback, closure, error prevention, reversal, locus of control, reduce memory load.

6. GUI Toolkits

Source

7. Human Factors & Cognitive Aspects of HCI

Source
Human factors refer to the physical, psychological and cognitive characteristics, capabilities and limitations of people that influence how they interact with computer systems. The purpose is to design systems that fit human capabilities rather than forcing users to adapt unnecessarily.

1. Human Perception

Perception is how humans receive, organise and interpret information through sight, hearing, and touch.

  • Visual perception — via text, colour, icons, images, size, position, contrast, spacing. A designer should use readable text, sufficient contrast, meaningful icons, and a clear visual hierarchy while avoiding clutter.
  • Auditory perception — notification/warning sounds, voice instructions. Should not be the only channel — some users can't hear it.
  • Touch perception — tapping, swiping, pinching, dragging; touch targets must be sized and spaced to avoid mis-selection.

2. Attention

Source
Attention is the ability to concentrate on particular information while ignoring other information. Human attention is limited — users cannot give equal attention to everything on a screen.
ExampleA university portal with 25 equally prominent homepage buttons makes a student hunt for "Course Registration." A better interface gives important functions appropriate visual emphasis — highlighting, grouping, spacing, reduced clutter.

3. Memory: Recognition vs Recall

Source
Recognition occurs when users identify information presented to them. Recall occurs when users must retrieve information from memory without it being presented. Recognition is generally easier than recall.
Interactive · Try both
Recognition: you see File | Edit | View | Insert | Help in MS Word and recognise the option you need — the choice is right there in front of you.

Because recognition is easier, HCI designers should provide visible choices whenever possible — e.g. a visible Save button beats requiring users to remember Ctrl+S.

4. Learning

A system should let a new user perform basic tasks without excessive training. Example An exam system clearly showing "Question 5 of 50" rather than leaving the student's position uncertain.

5. Decision-Making

Users continuously decide: which option to select, whether to continue/cancel, which payment method to use. Good design presents relevant info, uses clear labels, avoids unnecessary choices, and makes consequences clear — "Proceed to Payment" beats a bare "Proceed".

6. Mental Models

Source
A mental model is the user's internal understanding or expectation of how a system works, developed from previous experience, real-world objects, familiar software and social conventions.

Example: users expect a trash-bin icon to delete/discard, because they already understand a physical waste bin (ties into visual metaphors, §3).

7. Cognitive Load

Source
Cognitive load refers to the amount of mental effort required to understand information or perform a task. Human cognitive capacity is limited.
ExampleA course-registration system that forces a student to remember course codes, navigate unrelated pages, re-enter the same info, remember prior selections, and gives no progress indicator — places unnecessary cognitive demand. Fix: break tasks into steps, use familiar terms, provide defaults, show progress, give feedback.

8. Human Limitations

Users may forget, get distracted, misread, mistype, click the wrong button, misinterpret an icon, get tired, or decide under pressure. These are not incapability — they mean systems should never assume perfect human behaviour.

9. Human Errors

Source
A human error occurs when a user performs an action that produces an unintended result. A good HCI system attempts to prevent, detect, explain errors, and help users recover from them.
Interactive · Compare error messages
"Error 4738." — tells the user nothing about what went wrong or how to fix it.

Quick Revision — Human Factors

  • Perception: sight/hearing/touch. Attention is limited — emphasise what matters.
  • Recognition > Recall in ease — show options, don't require memorised commands.
  • Mental models come from prior experience; cognitive load must be minimised (steps, defaults, feedback).
  • Good error handling: prevent → detect → explain → help recover.

Likely Exam Questions

Likely Question

Q: Differentiate between recognition and recall, and explain why this matters for interface design.

Recognition is identifying information already presented (e.g. seeing a menu and picking the option you need); recall is retrieving information from memory with nothing presented (e.g. remembering Ctrl+S). Recognition is easier for users than recall, so designers should provide visible choices — like a Save button — wherever possible, rather than relying on users to remember commands.
📍 See §7 → Memory: Recognition vs Recall

Cognitive load is the mental effort required to understand information or complete a task. A registration system that makes students remember course codes, navigate unrelated pages, re-enter data, and gives no progress indicator increases cognitive load unnecessarily. It can be reduced by breaking the process into smaller steps, using familiar terminology, providing meaningful defaults, showing available options, and giving clear feedback.

Prevent errors, detect errors, explain errors, and help users recover from them. Example: instead of showing "Error 4738," a good system shows "Password is incorrect. Please check your password and try again," and may offer a password-reset option.

8. Interaction Design (IxD)

Source
Interaction Design is the process of designing the behaviour, structure and responses of interactive systems so users can accomplish their goals effectively and satisfactorily. It considers user goals, needs, actions, system responses, feedback, navigation, errors, and context of use.

User-Centred Thinking

A designer should ask: Who are the users? What do they want to achieve? What problems do they experience? What environment/devices will they use? What experience level do they have? This prevents designing purely from the developer's own assumptions.

Core IxD Concepts

ConceptMeaning
User GoalWhat a user wants to accomplish (e.g. a bank customer wants to check their balance)
User RequirementWhat users need from the system
PersonaA fictional representation of a typical target user (age, experience, goals, needs)
ScenarioA situation where a user interacts with the system to accomplish a goal
User JourneyThe sequence of stages a user passes through, e.g. Login → Dashboard → Course Registration → Select Courses → Review → Submit → Confirmation
Task AnalysisSystematic examination of the steps a user performs to reach a goal — reveals whether a process is logical or unnecessarily complicated
Interaction PatternA commonly reused design solution for a recurring interaction problem

Affordances & Signifiers

Interactive · Compare
An affordance is the possible action an element appears to allow — a button appears clickable, a text field appears typeable, a slider appears draggable.
Plain EnglishAffordance = what action is possible. Signifier = how the user identifies or performs that action. A button's raised, clickable look is its affordance; an underline on text is the signifier that it's a link.

Constraints & Mapping

  • Constraint — limits actions to prevent errors, e.g. a date field accepting only valid dates, or a Submit button staying disabled until required fields are complete.
  • Mapping — the relationship between a control and its effect should be logical/predictable, e.g. increasing a volume slider should increase the volume.

Feedback

Source
Feedback is the response provided by a system after a user performs an action. Users need to know whether their action was recognised and what happened as a result.

Quick Revision — Interaction Design

  • IxD = designing behaviour, structure, responses so users reach their goals.
  • Persona → Scenario → User Journey → Task Analysis, all rooted in user-centred thinking.

A signifier is an indicator communicating how to identify or use that action — e.g. underlined text signifying a clickable link. Likely Question

Q: List and briefly explain the nine stages of a typical Interaction Design process.

1) Understand Users — research who they are, their needs, context. 2) Identify User Goals — what they want to achieve. 3) Gather Requirements — functional and usability needs. 4) Analyse Tasks — break goals into steps. 5) Design Interaction — how users will complete tasks. 6) Develop Prototype — visualise/simulate the design. 7) Evaluate — test with users, collect feedback. 8) Improve — refine based on feedback. 9) Repeat — the process is iterative, looping back to Understand Users.

9. Prototyping

Source
Prototyping is the process of creating an early representation of a proposed system or interface for the purpose of exploring, communicating and evaluating design ideas.

Importance: test ideas early, obtain user feedback, identify usability problems, compare alternatives, reduce development risk and the cost of correcting design problems.

Likely Exam Questions

Likely Question

Q: Differentiate between low-fidelity and high-fidelity prototypes, stating one advantage and one disadvantage of each.

A low-fidelity prototype (paper sketches, basic wireframes) is a simple representation used for early ideas — cheap, fast, and easy to modify, but has limited realism and interaction, and may not reveal detailed usability problems. A high-fidelity prototype closely resembles the final system (colours, images, realistic controls) — more realistic and better for detailed usability testing, but requires more time/expense and is harder to change once significant effort is invested.

10. Design Evaluation

Source
Design evaluation is the systematic assessment of an interface to determine how well it supports users, whether it meets usability standards, and what needs improvement before or after deployment.

Formative vs Summative Evaluation

WhenGoalExample
FormativeDuring the design processImprove the design as it evolvesTesting wireframes/paper prototypes with users
SummativeAfter development / final stageAssess how well the final product performsMeasuring task completion rate in the finished app

Empirical Evaluation (User-Based)

  • Usability Testing — users perform predefined tasks; observers record time, errors, satisfaction.
  • Field Studies — observing users in their natural environment.
  • Interviews & Questionnaires — gather subjective feedback, preferences, pain points.
  • A/B Testing — users try two design versions; the better-performing one is selected.

Analytical Evaluation (Expert-Based)

  • Heuristic Evaluation — experts assess the interface against usability heuristics (e.g. Nielsen's 10 principles) — "Visibility of system status," "Consistency and standards."
  • Cognitive Walkthrough — experts simulate how a new user would step through the interface, identifying likely confusion points.

Usability Metrics

MetricDescription
EffectivenessCan users complete tasks correctly?
EfficiencyHow quickly can users complete tasks?
SatisfactionHow pleasant is the experience?
Error RateHow often do users make mistakes?
LearnabilityHow easy is it to learn the system?
RetentionCan users remember how to use it later?

Case Study: AAUA Student Portal Evaluation

AAUA's HCI team evaluated a new student portal before launch, combining Formative + Summative and Empirical + Analytical methods.

MetricBefore ImprovementsAfter Improvements
Task Completion Rate70%92%
Avg. Time per Task6 minutes4 minutes
User Satisfaction Score6.5/108.5/10
Reported Errors (per user)41

Key fixes traced to specific findings: "Programme Fees" renamed to "School Fees" (heuristic finding: match with real world); confirmation messages/loading spinners added (visibility of system status); text labels added beside icons (recognition over recall — an A/B test of icons-only vs icons+labels showed labelled icons were faster and gave users more confidence); navigation simplified (consistency); tooltips/hints added (help & documentation gap).

Quick Revision — Design Evaluation

  • Formative = during design (improve it). Summative = after development (assess the final result).
  • Empirical = real users (usability testing, field studies, interviews, A/B testing). Analytical = experts (heuristic evaluation, cognitive walkthrough).
  • Six metrics: Effectiveness, Efficiency, Satisfaction, Error Rate, Learnability, Retention.

Likely Exam Questions

Likely Question

Q: Differentiate between formative and summative evaluation, and between empirical and analytical evaluation methods.

Formative evaluation happens during the design process to improve the design as it evolves (e.g. testing paper prototypes); summative evaluation happens after development to assess the final product's performance (e.g. measuring task completion in the finished app). Empirical evaluation involves real users interacting with the system (usability testing, field studies, interviews, A/B testing); analytical evaluation uses experts applying usability principles without needing large user groups (heuristic evaluation, cognitive walkthrough).
📍 See §10 → Formative vs Summative, Empirical, Analytical Evaluation
Likely Question

Q: Using the AAUA Student Portal case study, explain how A/B testing and heuristic evaluation each contributed to the final design.

A/B testing compared two homepage variants (icons-only vs icons-with-labels); students using labelled icons completed tasks faster and felt more confident, leading to the decision to label all icons. Heuristic evaluation, done by three HCI experts against Nielsen's usability heuristics, found violations like missing status feedback and inconsistent icon styles — directly guiding fixes such as adding confirmation messages and standardising icon styles.

11. Emerging Human-Computer Interaction

Voice User Interfaces (VUI)

Allow users to interact through spoken commands (voice assistants). Advantages: hands-free, natural, supports users with disabilities. Challenges: accents, background noise, speech-recognition errors, privacy, and difficulty presenting complex visuals through voice alone.

Conversational Interfaces

Users communicate via natural-language conversation — chatbots, AI assistants. Instead of menu-hopping, a user can simply ask "How do I register my courses?" and get a conversational answer.

Multimodal Interaction

A system supporting more than one interaction method at once — e.g. voice + touch: saying "Open my results," then touching the screen to select a semester.

AI and HCI

AI supports intelligent assistants, predictive text, recommendation systems, chatbots, intelligent search, personalised and adaptive interfaces — interpreting user intent rather than just responding to commands.

Adaptive Interfaces

Change behaviour/presentation based on the user, environment, or context — e.g. an e-commerce app learning a customer's frequent searches and recommending related products.

Wearable Interfaces

Smart watches, fitness trackers, smart glasses — using touch, voice, movement, sensors and visual displays, important because interaction happens in different contexts from desktop computing.

Brain-Computer Interfaces (BCI)

Enable brain-activity signals to control a computer/device — an emerging area with applications in assistive technology, accessibility, rehabilitation, and medical research.

Ethical Issues in Emerging HCI

Privacy (how much data should be collected?), Security (how is it protected?), Bias (could the system be unfair?), Accessibility (can people of differing abilities use it?), Transparency (do users understand how it works?), Human Control (can users override automated decisions?).

Quick Revision — Emerging HCI

  • VUI, Conversational, Multimodal, AI-driven, Adaptive, Wearable, and Brain-Computer interfaces are all expanding beyond the traditional screen+mouse model.
  • Human-AI interaction concerns: Trust, Transparency, Explainability, Human Control, Privacy, Errors.

Likely Exam Questions

Likely Question

Q: What is multimodal interaction? Give an example combining two interaction methods.

Multimodal interaction is when a system supports more than one method of interaction simultaneously — e.g. voice + touch. Example: a user says "Open my results," and the system displays them; the user then touches the screen to select a particular semester.
📍 See §11 → Multimodal Interaction
Likely Question

Q: List and briefly explain the six key concerns in Human-AI Interaction.

Trust (knowing when to rely on the AI), Transparency (understanding how/why it produces results), Explainability (getting understandable reasons for decisions), Human Control (users can still control important actions), Privacy (AI processes large amounts of user data), and Errors (AI can be wrong, so users need feedback and correction paths).
